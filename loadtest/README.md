# Нагрузочное тестирование cat-api (Locust)

Стенд для Части 2 задачи «Работа с масштабированием»: поиск максимального числа
пользователей, которое backend (`cat-api-back`) обрабатывает корректно, и подбор limits.

## Состав

| Файл | Назначение |
|------|------------|
| `locustfile.py` | Сценарий: `GET /` (список котов, вес 3) + `GET /cats?cat_name` (вес 1) |
| `run_step.sh`   | Один шаг нагрузки + сэмплирование `kubectl top` на пике |
| `sweep.sh` / `sweep2.sh` | Серии шагов (100→1000 и 700→900) |
| `results_*_stats.csv`, `summary_*.txt` | Результаты прогонов Locust |
| `top_*.log` | Сэмплы потребления подов во время прогонов |

## Установка и запуск

```bash
python3 -m venv .venv && .venv/bin/pip install locust
# один шаг: <users> <spawn-rate> <run-time> <label>
bash run_step.sh 600 80 60s s600
```

### Настройки теста (Часть 2)

| Параметр | Значение |
|----------|----------|
| URL приложения | `http://localhost:8080` + заголовок `Host: cat-api.local` (через Traefik ingress) |
| Максимум пользователей | до 1000 (перебор) |
| Прирост пользователей/с (spawn-rate) | 20–100 |
| Длительность шага | 60s |

> Бьём в `localhost:8080`, а не в `cat-api.local:8080`, чтобы обойти ~5-секундную задержку
> mDNS-резолва домена `.local` на macOS. Host-заголовок подменяется в `locustfile.py`,
> Traefik роутит запрос по нему — то есть нагрузка реально идёт через ingress.

## Выводы

- **Узкое место — CPU.** Backend упирается в лимит **500m** уже с 300 юзеров и держится на нём.
  Память остаётся низкой (пик ~105Mi).
- **Максимум корректной обработки ≈ 600 пользователей**: запросы не падают (fails = 0),
  среднее время ответа 0.47 c (< 5–7 c). С 700 юзеров появляются отказы (~14%) — лимит CPU
  не даёт обслужить очередь.
- **Критическая точка** (600 юзеров): backend CPU = 500m (упёрт в лимит), MEM ≈ 85–105Mi.

## Новые limits/requests (по итогам теста)

Заданы в `helm/app/charts/back/values.yaml`:

```yaml
resources:
  requests: { cpu: "250m", memory: "128Mi" }   # база для HPA (target 60% => ~150m)
  limits:   { cpu: "1000m", memory: "256Mi" }  # запас CPU под burst; память по пику + запас
```

Дальнейшее горизонтальное масштабирование под нагрузкой обеспечивает HPA
(см. `helm/app/charts/back/templates/hpa.yaml`), вертикальные рекомендации — VPA.
